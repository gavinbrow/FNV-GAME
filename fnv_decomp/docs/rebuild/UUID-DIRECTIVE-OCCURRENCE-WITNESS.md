# Finite UUID directive occurrence proposal

`tools/rebuild/uuid_directive_occurrence_witness.py` is a pure, non-integrated source prototype for two pinned roots. It performs no filesystem access, COFF parsing, object reads, compiler or linker invocation, or output emission. It cannot select a library or approve a provider, certificate, graph, namespace, ABI, link, or runtime. The original negative certificate remains unchanged. Its output proposes three exact blocker occurrence mappings, including two distinct original ordinals with the same ID and digest, each mapped to its own directive ordinal and byte extent. The third occurrence maps to the complete ordered four-token sequence. Duplicate linker behavior and transitive library dependencies remain unproved.

`assess(root, contract, original_negative, raw_section, header, uuid_binding, authority)` accepts supplied facts only. `root` is the exact pinned root identity; `contract` and `original_negative` are the original singleton metadata records; `raw_section` is the complete 93-byte section; `header` includes all COFF section-header values plus physical index, object size, section count and optional-header size. The implementation conservatively requires zero virtual size/address, relocation and line counts/pointers, zero optional-header size and an in-bounds raw extent beginning after the complete section-header table. These requirements are predicates, not claims about the unobserved actual section. Four exact, case-sensitive directives must occupy the entire byte stream apart from ASCII whitespace; raw bytes and token spans are retained.

The `uuid_binding` object contains `kind`, `library_name`, `path`, `sha256`, `candidate_manifest_path`, and `candidate_manifest_sha256`. Its kind must be `bound-normal-sdk-search-candidate`; its physical path must have the basename `uuid.lib` (case-insensitive), and both paths reject control characters. This is a caller assertion about a physical SDK search candidate; the module neither opens it nor proves it was requested, selected, loaded, or semantically suitable. V12 contains no UUID request token; future use needs separate dependency and selection review. The `authority` object contains `root_sha256`, `contract_sha256`, `certificate_sha256`, `section_sha256`, `header_sha256`, `binding_sha256`, `candidate_manifest_path`, and `candidate_manifest_sha256`. Object-valued hashes use canonical JSON (sorted keys, compact separators, ASCII); section SHA-256 uses raw bytes. The fixed original certificate hashes and root identity are checked, but all other pins require independent caller source/input and peer review. Self-consistent caller-supplied pins are not authentication.

The 12 synthetic tests use invented payloads, headers, manifest paths and binding hashes. They temporarily replace only the fixed certificate hash in the in-memory fixture, so their success is not evidence of a matching actual certificate or directive section. Exact raw bytes, line metadata, actual binding and separately authorized collection are pending; no actual candidate should consume this prototype without the independent gates and reviews.
