# Fixed frontier diagnostic preparation

`tools/rebuild/application_frontier_diagnostic.py` prepares metadata and a LINK
response. It has no native invocation option. A separately reviewed, leased,
single-use driver performs any later diagnostic LINK; no executable is launched.

The fixed candidate cohort has 14,345 Game function providers and 44,540 retained
relocation fields. The ordinary prepared subset is 14,341; entry, overlay2 and
EHFile account for the remaining four. The delta from V6 is first3 ordinary
relocation members, CODE12 and EHFile: 16 providers and 187 fields. IOTask,
ModelLoader and the blocked DATA bridge are outside this cohort.

The actual three-component native conformance receipt and nine-export KERNEL32
receipt must match their accepted artifacts. The producer's nine-import join is
replayed against a fresh bounded archive parse. The new KERNEL32 library replaces
the eight-export predecessor; the other three import libraries stay the same.
All 27 candidate IAT aliases independently require exact original DLL/export,
native pointer/member/index proof, and every use of their canonical name in the
full field census. There are 399 IAT fields overall; an alias with any uncertain
use is omitted and its blockers are retained.

The separate CRT contract binds the entire field digest and 198 uses of four
existing names: 100 cookie checks, 94 cookie cells, one wide comparison and three
appends. The new generated EH cookie check keeps its generated-field evidence
class. The normal provider archive must equal the selected SP1 LIBCMT. Every old
CRT token is removed before the newly enabled subset is appended, so disabling
the coupled cookie pair cannot leave inherited aliases active.

The response changes output destinations, replaces the KERNEL32 library, adds
the three components and replaces the reviewed alias sets. It adds no logical
CODE alias by address or source spelling. All component exports, logical owners
and original function addresses were checked for conflicts by the accepted
field observation. Static archive candidates do not establish actual linker
member extraction.

Unresolved diagnostics, warnings, maps and raw logs remain evidence. A linker
success would not establish ABI, provider lifetime, startup initializer coverage
or runtime readiness. Normal library candidates and local tool support hashes
are not a complete transitive library or loaded-DLL closure.
