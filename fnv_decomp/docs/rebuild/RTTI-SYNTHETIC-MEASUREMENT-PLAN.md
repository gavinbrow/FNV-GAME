# Synthetic RTTI COFF measurement: bounded follow-on plan

The independently reviewed synthetic SP1 x86 compile-only phase produced one producer object and one consumer object; both compiler calls exited zero. The objects remain private. Neither was linked or run. The separate [runtime-driver handoff](CLAUDE-RTTI-RUNTIME-HANDOFF.md) owns a future source-only execution driver; this plan is limited to inspecting compiler-produced metadata and cannot establish runtime behavior or game ABI compatibility.

A future observer should accept only the exact two object hashes and source/compiler/flags bound by the private compile receipt, plus the exact independently reviewed receipt and source/driver identities. Check every bound input before and after. Read standard i386 COFF section tables, primary symbol and auxiliary records, and relocation tables, using an already reviewed bounded parser; never execute, link or load the objects. Do not inspect unrelated images, assets or original game binaries. Keep outputs private and serialize metadata only: section number/name/flags/extent, symbol index/name/class/section/value/auxiliary identity, relocation site/type/target, and explicitly classified compiler-generated RTTI and helper references. Do not publish code bytes or section payloads. Every count and graph edge must be backed by physical record identities; names alone are leads, not proof of a valid RTTI graph.

A versioned observation envelope should bind the original compile receipt and object/source/compiler hashes, parser and policy hashes, input identity and observation status. Preserve per-record source/object/section and physical symbol indices, graph edge provenance, type and descriptor role confidence, and any rejected/unknown/ambiguous records. Distinguish relocation evidence from claims about record contents, runtime address values or class layout. Count candidate type descriptors, complete-object locators, hierarchy/base descriptors, vtable references, and `__RTDynamicCast` / exception helper references only when the exact compiler-emitted metadata supports them. An omitted symbol, unsupported auxiliary or unclear relationship stays unknown; do not fabricate offsets, compiler layout, runtime behavior, or adopt any game provider.

Before any actual object read, independently review the exact observer, synthetic-only tests, parser bindings, allowed output and two hash-bound inputs. A separately coordinated read-only operation should then produce an exclusive private receipt and preserve failures, without replaying uncertain operations. Independent outcome review must reconcile counts and graph witnesses against the exact saved objects and receipt without extending the scope. Compiler-generated object metadata alone cannot establish which cast cases execute a helper or whether any runtime result is correct; those are distinct future tests. Native `DUMP` or any fixture link/run is outside this plan and needs its own reviewed operation if later useful.
