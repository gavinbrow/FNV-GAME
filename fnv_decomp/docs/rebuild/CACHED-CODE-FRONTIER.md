# Cache-backed CODE metadata qualification

`cached_code_frontier.build_recipe_contexts` is an explicit opt-in adapter for
the independently accepted lossless binding context cache. It reads one indexed
recipe frame through the frozen cache validator and calls the frozen ordinary
contract constructor for every requested singleton and the complete requested
recipe union. It retains the full recipe bucket for incoming-use and omission
evidence, including unrequested functions, missing fields and unknown row keys.
An empty binding bucket does not prove a function has no native relocations.
The inventory must label that coverage unknown unless a separate accepted native
observation proves it. Frozen contract completeness flags retain their original
meaning and cannot create such an observation.

Requested physical identities join both retained selection evidence and the
authenticated frame roster, including the native symbol slot. Each result
keeps original contract provenance separate from raw/compressed frame hashes
and original global row ordinals. Direct-stream and cached constructors must
produce identical canonical contract bytes with the same provenance.

This adapter creates metadata contracts only. It does not read original objects,
sources, reference images, archives or native tools, and does not run a closure
assessor, create certificates or approve serialization. Existing saved positive
and negative observations remain separate authority. Future production requires
its own original/native, namespace, operand and plain MATCH gates.

The full current frontier inventory is a separate reviewed operation. Before a
saved-data run, its source/input phase must bind the exact accepted cache receipt,
index and data, frontier review, planned identities, original metadata and current
prepared epoch. Per-recipe reads do not assert unrequested-frame freshness;
whole artifact fingerprints and terminal stability are operational obligations.
The existing 900-second, 1-GiB memory and 128-MiB output caps remain in force.
