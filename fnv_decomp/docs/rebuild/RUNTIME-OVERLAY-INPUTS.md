# Explicit alternate runtime object inputs

`runtime_overlay_inputs.py` normalizes accepted source-overlay objects into a
separate machine-readable runtime input registry and per-recipe root-observer
contracts. It performs no compilation, object rewriting, archive modification,
linking or execution. The original provider selection, retained proofs and
12,946-root CODE archive remain unchanged. Current ordinary observers do not
accept this new lane without an explicit overlay-aware adapter.

The fixed explicit selection is
`runtime/source-overlays/accepted-runtime-owner-selection.json`, SHA-256
`e879edf4f4ec4f8a2882972273c5858616cd6507d57e20a635dcd9cdd43aa72e`.
It requests thirteen alternate owners from nine exact accepted objects: the
two initial repairs, six-TU nineteen-field batch, and independently accepted
NiAccumulator address-carrier pilot. These contain 22 repaired fields and
931 complete original function rows. The remaining 918 same-TU function rows
are proof coverage, not additional alternate-provider selections.

The exact consumed receipts are the first-pair result

combined batch manifest
`5728021d6d5796f377bd3fbf02873db1d2b2d50e8d4bf2b2bfdff80409e97bec`,

`ec32d68580b62b225cd9e9e90e450a9915a39ab859b2c652105441d25b6ea9fb`,

Every referenced input, artifact and accepted compile profile is checked against
its own receipt. The compiler/header/context records remain historical evidence
of those accepted compiles; this observer invokes no compiler.

## Fresh physical evidence and original lineage

The one planned metadata operation opens only these nine original/alternate
object pairs, their exact sources and receipts, the pinned public recipe and
original proof/selection, bounded source-triage metadata and owned reference.
It verifies the exact frozen source transformations and complete saved function
row sets, then reruns the unchanged plain comparator on the existing alternate
objects for all 931 rows. The literal-name supplement is derived afresh and
must equal the previously accepted witness; no additional label alias is granted.

For every checked function, all non-field bytes and other reference names,
values, kinds, addends, type and linkage must agree with the original object.
Only the exact 22 requested operand fields and already proved compiler-literal
label rename are permitted. Actual old/new physical section and symbol indices
remain separate observations. All fresh source targets are independently joined
to original reference fields through the unchanged binding observer helpers.
Code targets must be existing checked defined entries; data carriers must stay
unique undefined EXTERNAL identities. No new storage type or code ABI is inferred.

The complete missing-field set for every observed TU must become exactly its
original set minus the approved repaired identities. Unrepaired fields,
including missing fields outside the entry-reachable selected subset, remain
explicit. The original reachable/global 47/88 censuses are never overwritten.
The operation also inventories every physical relocation in the whole alternate
object; fields outside checked code spans retain physical metadata without a
manufactured original data/EH address mapping.

Each registry unit retains these distinct lanes:

- **Original ancestry:** original recipe index/id and contents, original source
  and object hashes, global selected owner, original native placement and v3
  proof hash. Every original placement is reconciled against the unchanged v3
  per-function proof. These are never relabeled as generated source/object proof.
- **Actual alternate source/object:** generated TU hash, accepted compile receipt
  and operation, complete fresh comparison, exact resolver supplement, actual
  object hash and all fresh section/symbol/auxiliary/field identities. A separate
  `overlay-v1-...` unit identity includes the original ancestry, actual object,
  generated source and resolver identity.
- **Replacement dispositions:** only the thirteen policy-named addresses request
  alternate definitions. Their original selected recipe/symbol/span must agree,
  and original-to-new primary indices must be bijective within each recipe.
  Duplicate selected addresses across objects or a coalesced physical replacement
  reject the registry. Other same-TU functions retain their existing global
  selected provider, even when the alternate object also contains a definition.

Original EH observations remain explicitly tied to their original object and
are not a fresh overlay EH proof. The registry sets `fresh_EH_revalidation=false`.
Unknown EH, ABI, initialization, storage, import and lifetime obligations remain
for the future observer/provider contracts.

## Consumable output and root observer contract

`registry.json` records each normalized unit, exact object/source/recipe lanes,
replacement dispositions, migration count and all input/output hashes. Each
unit directory contains fresh `bindings.jsonl.gz`, `native-inventory.json`,
`comparison.json` and `source-and-replacements.json`. Repair and root binding
references hash the actual fresh rows, including their alternate unit/source/
object identity, rather than a pre-lane or original-object row.

`root-observer-inputs.jsonl.gz` contains nine complete versioned contracts. Each
has an exact whole requested root set and hash, new physical primary indices,
section/value/span, alternate definition ids, full binding ordinal/hash lists,
actual object path/hash, generated source proof and original ancestry. Complete
binding streams retain original target/base/addend roles, including IAT pointer
cells versus CODE and unowned DATA demands. Unrepaired root fields stay explicit
blockers. Parent-EH lineage and optional-index absence remain visible.

A consumer must explicitly support
`fnv-alternate-runtime-root-observer-input` and verify the whole contract/root
set, registry and detail hashes. `ordinary_v3_input_compatible=false` prevents
silently feeding generated hashes into an original-only input path. Recompute
root/retained-set closure, canonical-reference groups, aliases, omitted-definition
conversions and any projection comparison with the new object and exact whole
root set. Existing original certificates, plans and the frozen CODE archive
cannot be reused by replacing an object hash. Literal identity proves no provider
merge, and an address match alone does not resolve CODE/IAT/DATA roles.

Explicit alternate requests select the lane for metadata assessment only.
`adopted_for_link`, `provider_adopted`, `runtime_eligible`, closure and executable
states remain false. Nothing exports the other 918 definitions, materializes
storage or initializes a TU.

Outputs use a new exclusive private directory; input/output collisions reject.
The implementation hash is required at entry, and all inputs plus original
optional-index state and generated metadata are rechecked before publication.
An fsynced progress log preserves start, nine unit observations and terminal
status. Failure preserves its error receipt and separately rechecks protected
inputs. No scheduling, service mutation or GPU/model operation is involved.

Eight offline tests pass using public policy and synthetic objects. They cover
the fixed 9/13/22/931 scope, unaffected providers, extra references and changed
bytes, exact literal namespace exceptions, wrong original selection, coalesced
physical indices, complete missing migration, actual fresh-row hashes, whole
root coverage/new indices, old-v3 incompatibility and exact accepted compile
object/source/profile lineage. No actual registry metadata operation has run;
independent source/test review and explicit root go precede it.
