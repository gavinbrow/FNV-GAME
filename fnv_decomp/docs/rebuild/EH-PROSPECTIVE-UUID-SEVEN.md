# Prospective UUID-seven parent EH observation

This is a source-only design and collector. It authorizes no original object,
reference-image, SDK, compiler, linker or native-tool operation. The default CLI
validates a request without loading semantic producers or original inputs.
An actual `--observe` request needs a separately reviewed exact input envelope,
explicit root confirmation of the new original/reference scope, and a fresh
coordinator CPU reservation. Nonempty permission fields are operator context,
not authenticated approvals or cryptographic execution proof. Source review
does not grant the actual operation gate.

## Native graph and comparison contract

`prospective_eh_observe.inventory_parent` verifies the requested physical
symbol/section/value and reports parent section policy, actual associative
chains, named handler/FuncInfo/unwind candidates, all native code cuts, full
physical SafeSEH records, and state/action fields. Names alone do not establish
ownership. Foreign, ambiguous, absent, cyclic, catch/IP/type-list, unknown flag
or unknown state families remain explicit diagnostics. No 8-byte cleanup,
27-byte handler, single-state or no-catch assumption defines admission.

The caller supplies the exact original compiler buffer once per unit for graph
work, reusing it across the selected roots. Authentication precedes parsing:
bounded payload read, expected SHA, section count/declared allocation preflight,
then an exclusive SHA-identical private scratch copy for unchanged `Coff`.
The frozen parser's retained `.data` feeds the strict independent parser.
This scratch is copied compiler output, not serialized or newly authored code.
Its basename, hash and lifecycle are recorded; failures preserve scratch and
journal evidence. Successful cleanup checks owned file identities. Full input
integrity hashing before and after is additional I/O: one payload hydration is
not a claim of one filesystem read.

Each unchanged ordinary/EH comparison receives `functions=[exact_parent]`.
`eh_sections` itself supports this even when the retained verifier did not call
it because `eh_tails` was absent. There is no whole-unit EH comparison followed
by output filtering. The global recipe-name map is built once in memory and is
comparison context only. Inferred cleanup names remain separate observations,
not canonical providers or source-resolution proof.

Reference access starts with the selected parent. Each parent-targeted native
cut receives only its exact original field-derived interval. Other cleanup cuts
receive exact intervals from their owned metadata action fields. A handler
anchor never grants a whole `.text$x` window: noncontiguous cleanup placement
and unreferenced gaps must not permit unrelated code reads. The native cut and
original row join checks section, offset, length and independently derived
original start, including equal-length cuts. Data windows are bounded
comparison hypotheses derived from owned handler fields; they do not establish
object type, extent, storage or lifetime. Execution domains come from PE section
characteristics, not section spelling.

Ordinary errors, relocation observations, native physical fields, mismatch
offset/counts, every helper boolean and inferred name, and partial reference
reads on failure are preserved without code-byte payloads. Whole metadata
nonfields and supported relocation identities are compared separately. Unknown
metadata targets stay unresolved. Loader HIGHLOW validation is explicitly not
proved by this first observation family, so even a local metadata MATCH cannot
be a full closure certificate.

## Source request and future operation boundary

The source request has false root-scope confirmation, no reference path and no
image-gate input. It cannot run `--observe`. A future immutable request must
pin every semantic producer before fresh-process imports, the exact recipe and
baseline image gate used by unchanged `image_ok`, all four original identities,
the personally owned reference, prospective authority, output directory and
permission/lease context. The new root scope must explicitly include original
buffer hydration/integrity passes, private identical scratch, image hydration
and baseline fingerprint checks, and selected field-derived code/data reads.
None of that scope is established by this document or a successful authored test.

Proposed limits are four objects, seven roots, 16 MiB per original compiler
object and 32 MiB combined payload, 256 MiB declared parser allocation per unit,
64 KiB per parent-owned code/data span, 256 parsed unwind states, 8,192 reference
calls and 1 MiB accessed reference bytes per parent, 32 MiB result JSON,
540 seconds and practical 1 GiB peak process memory. Dedicated private output
directories are exclusive; journals and failed scratch remain private. No
serializer, compiler, linker, native executable or Game entrypoint is invoked.

All ABI, frame, provider, no-catch approval, runtime and complete-closure flags
remain false. Future findings select a separately reviewed witness family;
they do not automatically repair source, adopt aliases or materialize DATA.
