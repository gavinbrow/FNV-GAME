# Fixed nineteen-field compile-only batch

`entry_relocation_batch.py` implements the exact proposal in
[ENTRY-RELOCATION-NEXT.md](ENTRY-RELOCATION-NEXT.md): 19 new address references,
ten owners, six TUs and 619 complete original function rows. The first two-source
repair, earlier pilot, original sources/headers/recipes, retained proof, global
selection and original missing-field censuses remain unchanged. No native
operation has run for this batch. Source/test review and an explicit finite root
go are required before invoking its compile-only CLI.

The new fixed policy is
`runtime/source-overlays/entry-nineteen-existing-identities.json`, SHA-256
`0144fbdf83e055d2910989b9a06588334a0d6101c8f8bd9e98af77256e453029`.
It pins exact original source hashes, 16 guarded edits, copied existing
signatures/linkage/namespaces, existing opaque struct names and every proposed
target's own original recipe binding or checked function row. Six declaration
insertions replace existing blank lines; ten guarded function spans change
only their 19 literal operands. Original newline counts and all other source
bytes remain unchanged. No casts, template declarations, qualifiers, function
signatures or class definitions are changed. Earlier declarations refer to
existing identities; no opaque external storage type is manufactured.

The static include closures were resolved by following explicit include
directives from only the six named sources and discovered headers. No directory
or archive enumeration was involved, and no compiler was run for discovery.
The fixed source/header/compiler hashes cover all conditional include paths
encountered: archive has no headers, BSFile has one, AI has 16, PathingLocation
has 12, staging 009a has seven and staging 00b8 has eight. Actual compile include
paths must be a subset of that pinned closure. The sole source-side special
macro is the unchanged layout header's `__LINE__` static-assert macro; original
line counts and header origin are retained.

The CLI requires `--compile-only`, `--implementation-sha256`, `--reference`,
`--doctor` and a new private `--out`. It has no prepare-only mode. The supplied
reviewed implementation hash is checked before the operation and with all
other protected inputs at completion. Every reused helper stays unchanged.
Original source/recipe/selection, exact triage and reachable binding references,
retained object/proof, compiler binaries/code generators and bounded header
hashes are checked before use. The compiler retains each original recipe's
flags, with only original-source-directory include search and `/showIncludes`
recorded separately as context adaptations.

Each TU is compiled once. Its unchanged plain comparator must return the exact
complete recipe row multiset, all MATCH. The ten selected owners must retain
their exact compiled extents. For those ten owners, independent byte/relocation
geometry requires all 19 new fields to be exact zero-addend DIR32 references,
all non-field bytes equal and all other references equal. This additional raw
byte/reference equality claim is scoped to those ten owners; the remaining
609 same-TU rows have full plain original comparison and fresh binding coverage.
Code targets must be the exact existing defined entries with their original
native section/span identity; data carriers must remain exact unique undefined
EXTERNAL symbols. Physical indices are preserved as separate observations,
never assumed stable across compilation.

The unchanged runtime-binding observer helpers derive fresh source-bound fields
and original HIGHLOW correlations for every one of the 619 recipe functions,
using each fresh object's actual section/value/symbol indices and original
recipe mapping. The migration gate requires the complete new missing-field set
to equal the complete original set minus exactly the 19 authorized identities.
Unrepaired fields stay explicit; an unintended field removal or newly missing
field rejects the operation. Every repaired field additionally requires a fresh
exact source-resolution target, symbol and kind join. Compiler-literal pool
tolerance, numeric TLS offsets and unresolved storage/ABI roles retain the
unchanged observer's qualifications.

Two separate manifest lanes prevent old source-hash relabeling:

- `original-ancestry.json` records the original source/object/proof/recipe and
  original selected-owner ancestry, plus protected input pins.
- `runtime-overlays.json` records actual generated TU and fresh object hashes,
  new full function placements, fresh source-binding stream hashes, complete
  physical COFF inventory hashes, candidate-specific migration receipts and
  unchanged-comparator receipt hashes. The generated source has its own hash.

Each unit's private `source-bindings.jsonl.gz` repeats both lane identities on
every new row. `native-inventory.json` inventories every physical field in the
whole new object, all primary symbols, parsed auxiliaries, hashes of every
auxiliary record and section/COMDAT metadata. Fields outside original checked
function spans are physical metadata only: no original data/EH address mapping
is invented. These records support a future independent consumer; they do not
constitute alternate-provider selection, closure or adopted runtime inputs.
Current busy CODE producers and entry projections consume their existing
original lane unchanged.

Exclusive new output directories prevent evidence replacement. Each compilation
start and verification completion is durably journaled. Failures preserve the
generated source, object/logs and error receipt; they are not silently retried.
Source/object and every generated artifact are rehashed at completion, together
with protected original inputs and absent optional-index state. Observer elapsed
time and peak memory are recorded; compiler-child peak memory is explicitly not
measured. No linker, executable emission, native execution, new provider or
source adoption is present.
