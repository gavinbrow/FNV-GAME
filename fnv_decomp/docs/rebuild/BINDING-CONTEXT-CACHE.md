# Lossless saved binding-context cache

`binding_context_cache.py` is offside metadata preparation for future root collectors. It supplies exact saved rows to the frozen validators; it creates no function contract, closure/admissibility decision, native object, provider or runtime admission. Existing operators and frozen tools are unchanged.

The proposed operation traverses the saved decompressed binding rows once after independent source/input review and a metadata lease. It also reads the compressed file for hash verification before creation and again before and after publication: three compressed hash reads plus the one decompressed row pass. It does not claim one total physical I/O scan. ## Data and index format

The private output consists of one frame-data file, one JSON index/roster, one receipt and one progress journal. The data file concatenates 2,988 independent deterministic gzip members, one per authoritative recipe. Each member preserves the exact original decompressed line bytes, their order and line endings, including unknown fields and a final unterminated line. Rows are never normalized or reserialized. A zero-row recipe has an explicit empty gzip member and selected-function roster; it means no rows in this accepted source, not no native fields or complete runtime closure.

Each frame index entry binds recipe index/ID, original object/source hashes and recipe-unit proof hash, offset and compressed/raw lengths and hashes, original first/last/preceding global ordinals, exact row counts, event/class/kind/proof-consistency counts, missing counts and an original-global-ordinal semantic sequence hash. Compact roster tuples are `[original_address, symbol, section, value, size, symbol_index, row_count, missing_count]`. All 68,657 selected functions appear, including those with zero rows. This records physical source identity; it does not select materialized exports.

The top index binds the whole frame file hash/length, the SHA of all original decompressed bytes in order, complete row sequence/census, exact input hashes and all 2,988 frame entries. Frame offsets and ordinal ranges must be contiguous, with complete selected/physical uniqueness and explicit empty ranges. No fabricated field, root contract or metadata gap is inserted.

## Frozen validation seam

The producer feeds the exact captured raw bytes through unchanged `runtime_code_inventory.BindingReader` at hash `c2fdbd52b4b7f4b7c68f9d80ad03708ba57d42b29e5938dfcf9769366a1ffd0b`, calling its complete per-unit and final validation. Its source/proof roster uses the same frozen `check_unit` and `selected_rows` joins. A raw capture hash separately proves byte conservation rather than relying only on parsed JSON equality. Original function-field duplicates, foreign or unsorted recipes, stale physical spans, promotions and source census/sequence mismatches fail.

Future consumers construct `BindingContextCache(data_path, index_path, accepted_index_sha256)` once. It bounds and reads the index bytes once, hashes those exact bytes against the receipt, then parses/validates the same snapshot. `read_recipe(recipe_index, selections, unit, proof)` subsequently seeks only the requested compressed range. Streaming decompression enforces one gzip member, CRC/trailing/truncation limits and both compressed/raw hashes before returning. An ordinal-seeded subclass delegates all row validation to the frozen reader and preserves original global row identities. Returned full unit buckets can be passed unchanged to frozen `build_contract` and a separately fresh native-object observer. No existing operator has been switched to this cache.

Each bounded read verifies requested frame/index/source/proof/census identity and file stability. It does not reread or assert fresh verification of unrequested frames or the whole data-file hash. Expected index hashes must come from the accepted cache receipt; local Python objects and self-hashes are operational provenance guards, not authentication. Existing native-object hashes, original MATCH proofs, scope and eligibility checks remain separate requirements.

## Bounds and recovery

The unchanged operation limits are 900 seconds, 1 GiB sampled process peak and 128 MiB combined frame data, index, receipt and reserved progress budget. Per-line bound is 262,144 bytes, per-recipe row bound 150,000 and uncompressed frame bound 256 MiB. Decompression uses at most 1 MiB output chunks and a bounded line buffer, never a full 256-MiB raw blob alongside parsed buckets. Invalid or oversized inputs abort rather than increasing caps or dropping rows.

All outputs stay private and exclusive; original manifest source/object paths are reserved without opening them. Staging, fsync, exact generated-byte hashes and pre/post-publication input/tool/index checks preserve prior artifacts. Failed attempts remove only their own created outputs and retain the progress journal. Generation does not confer production admission.

The authored synthetic suite covers exact CRLF/unterminated bytes and unknown fields, zero-row recipes, missing records, global ordinal preservation, equality with direct frozen buckets and identical authored frozen contract/observer results, duplicate/foreign/unsorted/long rows, gzip CRC/trailing/truncation/concatenated-member errors, stale roster/proof/sequence/index/frame counts, output artifact drift and fixed resource flags. No saved source-stream pass had occurred at this source-first checkpoint.
