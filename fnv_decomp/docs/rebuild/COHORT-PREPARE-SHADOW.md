# Saved-cohort shadow qualification

`cohort_prepare_shadow.py` qualifies the narrow response-preparation seam using
complete, previously accepted V8/V9 validator results. This phase has no
production-admission capability. It does not reopen original inputs, Game
objects, archives, executables or native tools, and it changes no active wave.

The pure `evaluate_shadow(manifest, blobs)` consumes eight exact derived byte
roles: baseline result, response and outcome review; cohort result, response,
source/input review, prepared/driver review and outcome review. Each role has a
raw file SHA-256. The only profiles are the existing saved V8 and V9 cohorts.
The source, prototype and response-kernel identities are pinned, including
loaded module origins. Duplicate JSON members, nonfinite values, Boolean
counter substitutions and incomplete saved proof groups are rejected.

Every saved result is preserved as an unchanged raw JSON copy. Streaming typed
canonical digests additionally bind the entire JSON value, every top-level
value and the complete provenance. This distinguishes JSON `true` from `1` and
does not rebuild a smaller positive admission object from flags or counts.
The saved reviews are also carried unchanged, with their raw and semantic
identities. Unknown saved result fields are preserved; the input review's
complete raw byte seal prevents extra, missing or changed fields from silently
entering an approved cohort.

Historical aliases and CRT tokens are derived from both complete snapshots.
The explicit historical edit roles are checked against the exact paths fixed
by the frozen preparers and their saved six-field input identities. Repeated
identical binding rows remain present. A requested/resolved path, inode,
device, size or byte-hash difference blocks the role. These checks reuse
historical evidence: no historical library path is resolved, statted or hashed.
Provider `object_sha256` remains an original native-object identity, never a
substitute for the projected artifact's identity.

The frozen pure response kernel receives the historical target output
directory from the saved result's `@link.rsp` path. The new owned shadow
directory is a separate publication location. No path normalization or token
diff against the target response is used to manufacture equivalence. The
rederived physical response bytes must equal the accepted saved response.

Pure evaluation establishes equivalence and preservation only. It does not
independently re-admit the historical reviews or prove the original MATCH/native
semantics. Exact external source/input review is the sole acceptance of those
saved snapshots; it must bind the eight actual contents to their prior accepted
receipt and review lineage, rather than accept arbitrary nonempty JSON.

The CLI accepts only a hash-bound manifest and a hash-bound independent
source/input review. The review's exact schema binds all eight files, source
pins, profile and existing root authorization. Contradictory extra permission
fields are rejected. Actual roles must be JSON/RSP files within the ignored
derived-output root; authored tests use temporary fixture packages. No source
or command can be selected by metadata.

The operational runner reads only those eight files and the explicit control
and public source files. It records fresh identities only for those files.
Original MATCH, native conformance, namespace and physical-library identities
are named under `reused_checks`; saved input stability is not claimed fresh.
The output preserves complete result/review bytes, source lineage, historical
edit bindings, response/provenance equivalence and that distinction.

Output is exclusive. Copies and the pending receipt are fsynced and protected
by physical identity and byte hash before and after atomic hard-link
publication. A failed final check retracts only this operation's own terminal
link. Sampled bounds remain 900 seconds, one GiB peak memory and 128 MiB output;
raw derived inputs are bounded to 64 MiB each and 96 MiB total. Unsupported
sizes block qualification rather than dropping evidence or expanding limits.

The first stage is source review and authored fixtures. Only afterward may an
independent input review and the coordinator's metadata lease authorize a
bounded saved-cohort shadow. Exact historical manifests and reviews are private
derived artifacts. No automatic production adoption follows a passing shadow.

This qualification establishes preservation and response equivalence for the
closed historical profiles. It does not yet measure a reduction in setup time,
eliminate fresh per-cohort proof review, or qualify a future changed proof
policy. Future production integration must retain the full validators and
demonstrate an unchanged-policy cohort without a new Python fork; otherwise
the reuse seam should stop at this derived-only boundary.
