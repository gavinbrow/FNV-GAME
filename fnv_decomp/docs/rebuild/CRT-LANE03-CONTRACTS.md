# Lane 03 contracts for the normal CRT link plan

The accepted [lane 03 observation](CRT-FRONTIER-LANE03.md) supports fourteen
normal SP1 function models covering 360 exact original caller fields. The new
private `crt-lane03-link-contracts-v1.json` joins those models to their exact
canonical **code-role** undefined identities, native archive/member identities,
complete physical field proofs and explicit machine and state contracts. Its
SHA-256 is `57b28c34a30fcec1c1cf3626c7790dc8d171e922dc72a4a1a497276ad1852d73`.
Only saved packet, metadata, outcome, review and header receipts were read;
there was no additional image, archive or object inspection.

The saved lane packet contains **no actual V4 unresolved LINK group** for any
lane03 target. Consequently this supplement proposes zero current application
alias actions. Its concrete use is as a role-keyed join input for a later
included-caller census, rather than applying fourteen aliases to an unrelated
current cohort. A global alias resolves every included use of the same role
key; it cannot be constrained to one favorable source declaration. The three
failed direct models remain unmapped, and excluded/unclassified targets receive
no provider record.

`strcmp` and `clock` have sufficient normal machine-interface shape for a
diagnostic link contract, subject to inclusion review. This is distinct from
runtime approval: both have zero current V4 alias actions. The other twelve
records keep diagnostic binding false until their explicit remaining contracts
are reconciled. No file, heap, callback or EH boundary is waived to satisfy a
linker.

The records preserve all native dependency symbols and observed old destinations
as witnesses. Normal substitution instead uses one selected SP1 static CRT's
own errno, locale/codepage, invalid-parameter registry, FILEs, descriptors,
locks, heap, startup clock and ordinary OS imports. It does not require old
dependency-address equality, copy old state or forward into original code.
For stream and heap families, compatibility requires joint creation/use/cleanup
ownership across the included application; a leaf comparison cannot prove it.

The supplement emits no alias, object, library or executable. Provider selection,
runtime eligibility and runtime ABI approval remain false. Independent aggregate
review and the integration owner's exact included-caller join remain required
before any diagnostic projection is prepared.
