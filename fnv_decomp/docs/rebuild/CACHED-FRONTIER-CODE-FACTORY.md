# Cached native CODE factory

`tools/rebuild/cached_frontier_code_factory.py` is a finite adapter over the
accepted cached-contract native observation. It selects every positive
`SINGLE_ROOT_OBSERVATION` from the complete 180-singleton, 77-recipe,
257-record batch. Positive recipe unions remain evidence even when a union has
one root. Negative outcomes and their original blockers remain unchanged.

The accepted input currently identifies 59 positive singletons across 26 recipes
and 8,697 code bytes. The selector derives that entire set from the saved
receipt and stream; production cannot substitute a size sample or subset. The
operation also binds the independently accepted positive request, current V12
577-CODE demand set, original qualification request and reviews, and the latest
14,472 ordinary / 14,478 collision exclusion epoch. The selected application
cohort's 14,477 names are a separate set and count.

The accepted schema6 collision producer does not record an
`application_manifest_adopted` field. The adapter preserves that absence as
not recorded, checks the exact producer schema and its existing nonadmission
evidence, and rejects an explicitly promoted or malformed value. It does not
insert a replacement flag into the accepted epoch.

Every native record must match its original receipt ordinal and complete record
hash, frozen ordinary certificate, unchanged contract and qualification-row
hash. Source, object, recipe, provenance, export policy and no-admission flags
are checked explicitly. Qualification metadata is reconstructed without
restamping it. No negative certificate, typed witness or recipe union becomes a
bare positive provider. The three prior canonical-reference-group quarantines
remain excluded from the request.

The existing frozen context reader and protection helper are reused. A small
source-specific writer retains the accepted native observation unmodified in
the same indexed frame format; it does not add a legacy top-level provenance
alias. Every native record is validated before the stream can complete. Only
selected positive singleton frames are stored, within the unchanged 16-MiB
context cap. Saved frame bytes and the parsed-equal index are protected inputs
before any original source/object/reference read.

`prepare_operation(operation, inputs, start=...)` performs saved-metadata
admission without original input reads. The exact private output boundary is
validated early. A separate independent review binds source and operation hashes
and permits only the selected original inputs, source hashing, immutable checked
reference and private CODE output. The source owner cannot sign that review.
Native tools, executable linking and Game execution remain disabled.

The retained reference-image authority is the exact `build/image_check.json`
record, SHA `c03da09d39b8fd22283792c3dc1fbb6ac1e526d8afadd832fabc4071f1720cb1`,
also bound by the retained verification input. `doctor-all.json` is separate
toolchain/environment evidence and cannot substitute for that image-check role.

Projection calls the unchanged frozen zero/field consumers and ordinary
comparison helpers. Original objects and source hashes are checked afresh; the
original HIGHLOW and operand audit remains mandatory. Each emitted member needs
full original and staged plain MATCH reports plus independent COFF reparsing.
The field consumer's structured `UnsupportedRoot` policy assessment can
quarantine a root. Hash, graph, source, operand, map, serialization and comparison
errors abort the whole operation; there is no broad exception-to-policy waiver.
The original ordinary certificate is neither edited nor replaced.

The full original field-proof stream copies every retained source field,
including original `import_id` and classification data. A zero-field member has
an explicit empty proof record. Unit-wide IAT context, including import175,
never invents a root import use. The reused proof schema's historical
`central_record_sha256` field is the unchanged cached-native record hash; the
explicit authority kind and `native_observation_record_sha256` identify its
actual source, without claiming a legacy central envelope.

The archive, symbol index, recovered byte-identical members, physical maps and
all terminal root statuses are independently reviewable. Output includes the
complete 257-record native ledger, 577 current CODE planning rows, and 68,657
original physical owner coverage rows. Unknown or previously blocked demands
remain represented; prepared and selected application namespaces are not
inferred from matching counts.

The bounds remain 900 seconds, 1 GiB sampled peak memory and 128 MiB private
output. Native records and selected frames are streamed. Large admission
metadata is released before loading the original image, and one selected raw
object is retained at a time. Every requested positive singleton must be emitted
or explicitly policy-quarantined; integrity failures leave an aborted attempt
without an accepted receipt. The frozen atomic publisher is reused with an
exact terminal-receipt byte postgate.

CLI arguments are `--operation`, `--operation-sha256`, `--review`,
`--review-sha256`, `--reference` and `--out`. The closed operation keys,
artifact pins and independent review schema are defined in the source. The new
private output is `build/rebuild/cached-frontier-code-v12-v1`; earlier archives,
epochs and producers remain unchanged. Source/authored tests do not claim a
production outcome or provider, ABI, application or runtime readiness.
