# Prospective EH saved-graph join

This source-only draft consumes one already-decoded singleton graph record per call. It opens no files, reads no objects or image, starts no processes, and has no CLI or production consumer. The seven hard-coded roots and four object hashes constrain its scope; the 2770 historical root is not admitted. Caller-supplied canonical JSON hashes are comparison expectations and do not authenticate the graph operation, its review, or the caller. The recipe ID and complete symbol, section and index descriptor are checked for internal consistency only; their authenticity requires separately reviewed external caller authority.

The join checks record, certificate, contract, scope, graph-edge and physical-disposition digests; hard-coded root address, recipe index and object hash; internal consistency of the caller-supplied recipe ID and physical symbol descriptor; direct association edges; selected physical relocation target indices; and each reported SafeSEH target index. It returns only direct association candidates, physical relocation candidates and reported SafeSEH entries, preserving graph blockers. It does not infer EH ownership, prove table completeness, approve omissions, or join an unrelated sibling root's children. Output remains unverified even if internally consistent.

The 14 metadata HIGHLOW sites and raw operands, handler/cookie/cleanup semantics, frame and no-catch class, historical compiler/source lineage and current source binding all remain open. A graph certificate cannot establish those facts. Additional collectors require separate exact source and input review, authorized operation scopes and fresh resource gates; there is no implicit second four-unit capture. Blocked DATA remains unknown. The existing ordinary plain MATCH and specialist reviews remain mandatory before any later admission.

The broad55 saved output is pending independent outcome reviews. Do not run this draft against it until those reviews accept its exact artifacts and a separate reviewed input/adapter plan binds the singleton records. The tests use authored dictionaries only. No synthetic result is production evidence. All admission flags stay false and `discharged` is empty.
