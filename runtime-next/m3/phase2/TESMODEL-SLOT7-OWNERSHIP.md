# TESModel slot 7 ownership evidence

Five separately RTTI-anchored original tables—TESModel, TESModelRDT, TESModelTree, TESModelPSA and TESModelAnim—share seven corresponding entries followed by the relocated target `0x00acbb70`. An independently anchored TESModelTextureSwap table has the same slots 5 and 6 and uses `0x006815c0` at the corresponding slot 7. Both targets are tiny x86 member-shaped functions: the former returns zero in EAX and the latter returns `this`; neither reads a stack argument. This pattern strongly supports an inherited eighth virtual and a TextureSwap override. The targets also have unrelated source uses, so their shared addresses do not identify their historical names or exact return types.

The original TESModel table at `0x0101cf44` is immediately followed after eight relocated code pointers by a mapped literal at `0x0101cf64`. TESModelAnim's table at `0x01049e48` is likewise immediately followed by a mapped literal at `0x01049e68`. TESModelPSA's `0x0104540c` table has eight relocated pointers, a zero word, and the mapped string beginning `0x01045430`; TextureSwap similarly has a zero after its eighth pointer before its neighboring mapped string. These independent neighboring boundaries support eight slots in the model family, although no individual zero word proves a table boundary or array ownership on its own. TESModelTree's following word is a separately relocated COL, reinforcing the need to use the complete locator rather than scan a run of code pointers.

The first four slots have bodies in `fallout_shared/tesmodel.cpp`: `0x00489040` clears model string state; `0x004890e0` forwards to the texture-list member; `0x00489430` is a `BaseFormComponent*` copy view; and `0x00489480` compares through a `BaseFormComponent*`. The x86 body at `0x00408da0` returns a string pointer; the `0x00489100` body accepts one stack argument and writes the string, and unit 620 calls its current slot-6 declaration with a model path. These support the current ABI shapes. They do not prove historic names, const qualification, or an exact semantic type for slot 7. `bgsbodypartdata.h` contains method-description comments including a `FileEntryList*` getter, but does not identify its slot or prove it corresponds to the null/self pair.

The earlier seven-slot candidate is incomplete. A private eight-slot ABI experiment could add a placeholder returning an opaque pointer with no arguments, but it must be described as a transport-level hypothesis, not a recovered semantic method. A canonical header shared by units 620/621 should wait for a source or caller tying slot 7 to its returned type and for precise virtual contracts; the existing units differ in BaseFormComponent declarations, model fields, and BSStringT/include ownership. Verify all functions, constructor/destructor and EH, RTTI and placement when testing the eight-slot hypothesis.
