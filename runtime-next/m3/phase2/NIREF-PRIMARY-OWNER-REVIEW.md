# NiRefObject primary destructor and deleting-wrapper ownership

The accepted 825d public `fnv_decomp/include/NiRefObject.h` already declares `virtual ~NiRefObject();` out of line. Its 18-byte optimized definition is local to unit 1503's `nishaderfactory.cpp` at the `inline NiRefObject::~NiRefObject()` definition, rather than in the header. That source decrements `ms_lObjectCount` using `NiAtomicSubtract`. Unit 1503 is `/O2`; its saved combined-fixture object has an 18-byte native destructor, and its generated G deleting wrapper changes from 42 bytes with unsized global delete to 44 bytes with proposed sized NiMemObject delete. The corresponding reference functions remain distinct from the primary `/Od` pair.

Unit 612 (`animation.cpp`, `/Od /Oy- /GS /EHsc /Gy /GF`) currently owns the separate 33-byte `0x00496910` free-function source view and 46-byte `0x004968e0` EBase surrogate wrapper. The former stores the reference NiRefObject vtable then calls `0x004019a0` on `0x011f4400`; the latter calls that 33-byte body, then conditionally calls sized deallocation `0x00aa1460` with size 8. Unit 633 source at `0x004019a0` explicitly forwards to `InterlockedDecrement`. Thus the source and mapped helper support decrementing the shared counter, but the names and caller conventions of the current surrogates do not by themselves establish native destructor ownership. Frozen 6757 and 825d unit-612 recipe entries are identical; archived unit 612 object SHA-256 `a35fabf5dd1507a6845a679db063849db797ac085d3cd5dcf2f97c132f735e62` passes 154/154 strict functions and has zero ordinary EH section failures/errors. Both target functions individually match the reference.

Original NiRefObject RTTI and source support a virtual destructor at observed slot 0 and `DeleteThis` at slot 1 (+4 bytes); unit 1484's source-owned `DeleteThis` at `0x00cfcc20` dispatches deletion. An observed two-entry pointer prefix is not a complete vtable-extent proof. The optimized `0x00a5d3d0` destructor remains a separate 18-byte mapped function in unit 2725. No same-address or same-name alias collapses these owners.

The candidate integration difficulty is real source closure: unit 612's `animation_decls.h` currently defines its own `class NiMemObject` with allocation declarations; directly including the public NiRefObject header also includes `NiMemObject.h`, producing a duplicate definition unless that existing declaration is reconciled. The proposed public NiMemObject API uses the corrected `struct` class key; both scope/first-declaration consistency and all affected animation layouts need testing. The 6757 quoted-include cohort inventory already identifies 118 units / 1,926 mapped functions whose captured closure includes public `NiRefObject.h`; the 825d transition and preprocessing can alter actual reachability. A lexical source search found 44 files containing NiRefObject definition-shaped text, including namespaced/local views and comments; it is not a count of global ODR-equivalent classes. Existing inline definition in unit 1503 must be reconciled before any global out-of-line definition is installed.

## Out-of-line fixture result and inline hypothesis

The saved unit-612 out-of-line fixture passes 154/154 mapped functions, but unit 1503 drops from 11/11 to 10/11. Its mapped destructor at `0x00aa05a0` changes from 277 bytes to 269: the original inlines the NiRef vptr store and atomic decrement, while the candidate ends in a tail jump to external `NiRefObject::~NiRefObject`. This is a real optimized code change, not a literal-label mismatch. The separately archived unit-2725 18-byte physical destructor still matches its original reference.

A separate private inline hypothesis under `../out/phase2-niref-primary-inline-fixture` places one source-supported inline destructor body in the canonical header mirror, removes the unit-1503 local duplicate, and changes the existing unit-612 surrogate destruction call to the NiRefObject type. This is an uncompiled experiment: it must naturally emit the source-owned 33-byte destructor and 46-byte deleting wrapper, and its inline atomic helper may generate a different `/Od` call shape. The experiment adds no noinline directive, emission-only function, reference-only alias, or source data definition. The public-header change requires at least the existing 118-unit quoted-closure cohort to be retested, followed by compiler include traces, ODR/provider and full image gates.
