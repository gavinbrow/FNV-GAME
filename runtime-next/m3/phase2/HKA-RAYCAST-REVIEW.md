# hkaRaycastInterface source review

The reference hka table at 0x010c4b60 has three observed slots, with source owners all in unit 1711 (`hkafootplacementiksolver.cpp`, /O2): slot 0 is 0x00c74e70, a 33-byte surrogate setting the base vptr and conditionally releasing `this`; slot 1 is 0x00cd8810, a 10-byte const virtual returning a one-byte CD8810Bool with five opaque pointer parameters; slot 2 is 0x00cd8800, a 10-byte stdcall free function that zeroes its first pointer argument and ignores four integer arguments. Source-level declaration does not itself establish the virtual member signature.

The bhkRagdollController table at 0x010c4ddc has slot 0 at 0x00c7de30 (unit 260, a 44-byte surrogate wrapper), shared slot 1, and slot 2 at 0x00c77460. That last unit 2773 method uses an explicit bool output pointer, two Vec const references, a float pointer and a Vec reference, returns the bool pointer, and performs actual ray/cache operations. The ABI resemblance to the base no-op stub is a lead; the source provides no proof that the reconstructed signature is the historical native virtual contract, return wrapper or parameter identity. Caller-side argument and return use, layout, deleting-destructor body/ownership, class hierarchy and complete table need independent proof before creating a canonical header.

Unit 260 BaseC7 currently declares three virtual methods followed by a virtual destructor, which does not match the observed three-slot table. A function-body match for the 822-byte controller destructor is not class conformance. No protected edits or candidate aliases were made.

## Caller ABI constraints

Reference disassembly at 0x00cd8800 loads the first stack argument into EAX, writes zero to the byte it points to, and returns with `ret 0x14`; at 0x00cd8810 the corresponding cleanup is `ret 0x18`. Both leave ECX unused and return the buffer pointer in EAX. The latter agrees with the source `CD8810Bool` one-byte class, user-provided bool constructor, and virtual member with five explicit pointer parameters: a hidden return buffer plus five arguments explains six words. The former admits a hidden return buffer plus four parameters, consistent at the machine level with ControllerRay's explicit output pointer plus four parameters, but does not prove original aggregate type, const qualification, or override. Unit 1711 has no typed virtual callsite beyond the declaration; full caller-side argument and return consumption remains open.
