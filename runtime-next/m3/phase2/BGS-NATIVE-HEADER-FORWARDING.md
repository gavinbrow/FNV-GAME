# BGS native header forwarding scope

The tested rebased 620 and 621 private fixture directories each contain five byte-identical native class header copies. No corresponding `_native.h` files currently exist in either live `include/` or `src/fallout_shared/`. Thus the present duplication is between private translation-unit fixtures, not already duplicated live source definitions.

A private v1 public-header/forwarder experiment exposed a real lookup change: when the canonical native TESModel header moves to `include/`, its quoted `BaseFormComponent.h` resolves to the public wrapper rather than the original `fallout_shared` wrapper; `FileEntryList_native.h` likewise finds the public rather than local `layout_support.h`. Those wrappers have shared guards but different content and packing. V1 is preserved as a negative context finding and is not suitable for integration.

The v2 candidate gives each native class one definition-bearing public header, plus a distinct-guard local forwarding wrapper. The wrapper chain first includes the same local prerequisites in the original order: TESModel includes local BaseFormComponent and FileEntryList; FileEntryList includes local layout support; PSA includes local TESModel; BGSBodyPart includes local PSA then BodyPartInfo. The unchanged public definition headers are then included. The lexical graph now includes the original local prerequisite edges before the public equivalents; because this scanner does not evaluate include guards, it does not prove which declarations are active. The unit 620 and 621 production-layout candidate trees and all captured paths/hashes are in `out/phase2-bgs-native-header-forwarders-v2/manifest.json`.

Before adoption, compile both prior and forwarded contexts under actual production include order and inspect `/showIncludes` and preprocessor guard/pack histories. Require all 15+10 mapped functions, source-bound literals and ordinary EH, the PSA/BGS RTTI, weak/COMDAT ownership and final placement. Also enumerate any future local wrapper consumers from their full closures. Existing alternate TESModel, FileEntryList and BGSBodyPart source views are outside this two-unit fixture; their inclusion is not authorized merely because names match.
