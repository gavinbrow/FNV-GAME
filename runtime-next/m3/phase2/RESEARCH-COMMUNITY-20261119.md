# Community source and table research — 2026-11-19

Scope: bounded reading of public repository pages and existing local evidence; no downloads, imports, external execution, source changes or builds. Links below point to moving branches, so a future reproducible experiment must pin commits and file hashes. No class or byte count is newly accepted.

## Representative classes

- **TESContainer:** [yUI CommonLib](https://github.com/yvileapsis/yUI-NVSE/blob/main/CommonLib/Bethesda/TESContainer.hpp) declares a 0xC BaseFormComponent, a list at +4, and FormCount fields count/form/extra. This supports a compact comparison against the existing 12-byte local canonical object and its typed list; it is a plugin-facing declaration, not evidence of every virtual or cross-unit definition. Record whether its extra type is actually used and independently verify offsets/aliases in the reference.
- **TESModel:** [yUI's TESModel](https://github.com/yvileapsis/yUI-NVSE/blob/main/CommonLib/Bethesda/TESModel.hpp) gives 0x18, BaseFormComponent, model string, texture data and facegen flags; it calls slot 7 `bool Unk_07()`. Local caller and TextureSwap evidence instead supports a pointer-valued source view; this is a real return-type conflict, not a field to import uncritically. Our prior 8-slot observation does not make yUI's signature correct.
- **BGSBodyPartData:** [yUI](https://github.com/yvileapsis/yUI-NVSE/blob/main/CommonLib/Bethesda/BGSBodyPartData.hpp) models three bases, 15 body-part pointers at +0x34 and ragdoll pointer at +0x70, 0x74 overall. The xNVSE member-versus-base discrepancy noted in NON-AI-RESEARCH remains; compare actual COL/BCD/PMD, constructors and virtual tables before class adoption. Matching size and fields alone do not settle inheritance.
- **ImageSpaceModifierInstanceDOF/DRB:** in this bounded search [xNVSE GameObjects.h](https://github.com/xNVSE/NVSE/blob/master/nvse/nvse/GameObjects.h) exposes a DOF pointer use but no inspected class definition; no independent community hierarchy was established. Existing local unit773 reference graphs and compiled source candidate already show why the extra allocation mixin cannot be assumed; do not infer a matching declaration from the pointer name.
- **NiRefObject:** [JIP netimmerse.h](https://github.com/jazzisparis/JIP-LN-NVSE/blob/main/internal/netimmerse.h) models an 8-byte object, NiMemObject base, two virtual entries and reference count +4. Its first entry is a `Destructor(bool freeThis)` plugin ABI view, not proof of the exact native C++ destructor signature or COMDAT ownership. Local primary 33/G46 versus optimized 18/G44 differences and incompatible inline visibility remain unresolved. NiMemObject is spelled class there, while the inspected PC reference RTTI records a struct; preserve that evidence conflict.

## Structured-data pilot

[xNVSE CommandTable.h](https://github.com/xNVSE/NVSE/blob/master/nvse/nvse/CommandTable.h) documents a 0x28 CommandInfo with names, opcode, 16-bit flags/count, parameter pointer and execute/parse/eval pointers, plus a three-field ParamInfo. It provides a concrete reusable schema for checking the already generated command-table prefixes and unresolved tails, rather than commissioning one task per row. The xNVSE [plugin command definitions](https://github.com/xNVSE/NVSE/blob/master/nvse/nvse/Commands_Scripting.cpp) are extension-owned records, not proof that a named record exists in the retail image. Separately, [JIP's registry](https://github.com/doodlum/JIP-LN-NVSE-Library/blob/main/jip_nvse.cpp) registers plugin opcodes and must not be confused with the executable's original command table. [xNVSE GameSettings.h](https://github.com/xNVSE/NVSE/blob/master/nvse/nvse/GameSettings.h) is a lead for setting classes; this inspection did not certify any individual retail global extent. Havok reflection names and class descriptors are a promising independent executable-backed table source but no specific reflection table/schema was verified here; keep it a lead.

Suggested low-cost pilot: pick 10 contiguous rows in an existing accepted retail command-table prefix and 10 adjacent unresolved rows only where independent original extent exists. Join by original VA, pointer relocation sites, string identity, opcode and 0x28 stride; classify complete records, boundaries/partial records, null pointers and conflicts. Output metadata facts and differences only, preserve raw byte ownership, and use existing compiler/relocation/image gates before any type selection. Count separately records already typed, newly source-supported complete records, unresolved rows, and accepted output; this sample estimates usefulness, not a Phase 2 completion rate. A similarly bounded settings sample can follow only after its actual executable storage and descriptor are independently identified.
