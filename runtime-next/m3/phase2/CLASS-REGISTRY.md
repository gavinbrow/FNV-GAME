# Reference-name and source-definition registry

`rtti_class_registry.py` builds a private evidence registry from the reference-assisted class census, all local `src`/`include` C++ files, literal quoted-include relationships and the units recipe. It reports declaration paths/lines, class-versus-struct spellings, lexical token fingerprints, and recipe units that can reach a definition via that conservative include graph. No source bytes are copied into the report. The output is `out/phase2-rtti-class-registry/class-registry.json` and is created exclusively.

The saved run scanned 5,486 C++ source/header files and found 1,963 simple reference-identifier groups: 1,134 with multiple lexical definitions, 522 with one, and 307 with none. One quoted include name (`string.h`) was unresolved within the project roots and requires system include-path handling. For the concrete shared-class candidate, `BGSEncounterZone` has nine lexical definitions and seven distinct lexical token fingerprints; its unit-2 declaration header is reachable, while a second similarly named header is not reachable from the current recipe. `TESForm` has 333 lexical definitions and 224 token fingerprints. These counts include variants and local/namespaced declarations, and are not a count of actual ODR violations or merge work.

This is a prioritization and collision-evidence registry, not a C++ parser: namespace binding, macro/preprocessor conditions, compile flags, exact include search, packing, access and ABI are not resolved. Equal token hashes do not establish type compatibility; differing hashes do not by themselves prove a collision in a linked program. Use the graph, complete recipe and compiler/reference comparisons for each proposed merge. `rtti_test_registry.py` covers comment/string masking, balanced bodies, quoted includes and malformed declarations without compiler use.
