# Candidate-specific PSA weak search design

Status: research design only. Existing weak mode remains disabled in the accepted configuration, and its `coff_weak.resolve_fallback` deliberately rejects characteristic 2. No ordinary E-address alias is authorized. This design describes the effective pipeline namespace, not a general MSVC linker implementation.

A build-local capsule must be assembled after the actual compiler and before placement. It must identify the recipe, exact completed-successful unit index list, every object SHA-256 and complete primary/auxiliary COFF symbol table, generated M3 objects/manifest and active DV1 pseudo-units, actual phase0 and placed state, exact V7 name records/ICF/conditional name and field overlays (including explicitly recorded absence), import maps, serialized contribution/EH pieces, toolchain/compiler and resolver hashes, and effective driver configuration. Verify hashes at consumption and after build; reject missing, duplicate, changed, unparseable, unexpected or unaccounted providers. The 2,995-object hybrid experiment and saved prior-run state are diagnostics only.

For both actual libcmt and libcpmt archives, pin their full hashes and enumerate all members and full symbol tables, including code-only members omitted by data-v1 pseudo-units. Validate archive member boundaries, both archive linker indices and their consistency with enumerated strong external definitions; fail closed on unsupported member formats, missing indexed providers, ambiguous definitions or archive/search ordering that is not modeled. A library member advertising a strong E is a blocker, not an excuse to follow G. Also check actual recipe/global strong function maps, unit maps, imports, placed data globals, M3, ICF and every applicable V7 overlay under the real resolution precedence. Distinguish absence of a file from an empty overlay.

Use a narrowly enabled request containing a build capsule digest, origin unit and object digest, exact section/relocation identity, primary decorated symbol and weak auxiliary index. Validate raw primary/aux records via existing helper including reserved bytes, type, target index, cycle and alias checks. Run ordinary strong-primary lookup and all precedence-applicable authoritative overlays first; a unique strong provider wins normally, and conflicts fail. Only an unresolved E at the evidenced PSA site, with characteristic 2 and validated complete absence of a strong E in this sealed namespace, may request a fallback. An ordinary strong E name address must never be inserted.

Resolve the auxiliary G through the same existing source/recipe/local-owner resolver, without reading the reference field or using a name-embedded address as the target. Prove that it is the candidate unit 620 emitted function with a unique 44-byte mapped source owner at 0x005e3c30, and that its normal resolved destructor and delete relocations, full body and extent match the source-backed original owner. Separately prove the 19-byte implicit destructor owner and ordinary EH plus candidate/source ODR and COMDAT selection. Conflicting fallback definitions, unknown selection or multiple physical owners without a proven selection block the operation.

The field placement must be established independently: identify the selected vtable section, its exact relocation offset, ownership, exclusions/overlaps, and actual post-layout destination from the run's placed state. Only after resolution may an independent comparison verify that the resulting output field agrees with the original and that relocation encoding/addend is correct. The reference value is a verification outcome, never the source of the binding. Resolve all other table fields and compare class layout/RTTI before claiming an emitted full native table.

Minimum adversarial tests: absent or stale capsule; changed unit or archive member; malformed table/aux/index, unsupported archive form, cyclic weak chain, extra strong E in any object or archive, duplicate/ambiguous G, conflicting overlay/ICF, changed provider order, local-versus-global precedence, wrong section/field/addend, wrong owner extent/body/relocation, changed reference field (must fail verification without altering computed target), duplicate COMDAT ownership, and weak-off regression. Tests must prove no opt-in affects unrelated weak records or existing mode-0 output. Then require fresh full positive, repeat, targeted negative controls and actual image/relocation/semantic gameplay verification before considering promotion.

Open gaps: no capsule exists for the actual 825d run with all archive code members and candidate placement; the saved positive places a unit620 E-containing data section at 0x0104541c but phase0 source is null, which does not prove resolution or splicing. Native table ownership, full emitted 8-byte region and post-layout outcome remain unproved. The 44-byte G and 19-byte dtor evidence supports body identity, not historical source identity or whole-class acceptance.
