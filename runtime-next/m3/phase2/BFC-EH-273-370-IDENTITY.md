# Unit 273 and 370 EH target identities

Unit 273's constructor `0x008c9330` has source member `M1` of size `0x38` at `this+0x40`. Its original constructor calls `0x008c8830` on that member. Its reference cleanup relocation field at `0x00f1596f` targets `0x008c8890`. Independently, the same unit's source destructor view `FUN_008c9430` contains a `FUN_008c8890_m` member of size `0x38` at `+0x40`; original destructor instructions at `0x008c94b7..0x008c94ba` pass that member to `0x008c8890`. The existing unit recipe binds `??1FUN_008c8890_m@@QAE@XZ` to that address, and the source has an independently mapped body view `FUN_008c8890_shell::FUN_008c8890` at the same address. This supports testing a unit-local `??1M1@@QAE@XZ -> 0x008c8890` binding or reconciling the source view types. It does not prove original historical class naming or justify a global same-name binding.

Unit 370's source constructor `0x00913fe0` declares two distinct one-word members `m_11c` and `m_120` as the same surrogate `FUN_00528cb0`. The source calls `FUN_006f74f0` on the former and `FUN_0092c8b0` on the latter. In its archived COFF cleanup section, two distinct funclets both relocate to the same surrogate destructor spelling; the original cleanup at `0x00f16f3c` for `this+0x11c` targets `0x0044cbf0`, while the cleanup at `0x00f16f4a` for `this+0x120` targets `0x0092c890`. A single symbol binding cannot satisfy both.

The same unit separately declares one-word `PtrA96` and `PtrB96` views, with the respective source methods `FUN_006f74f0` and `FUN_0092c8b0`; its existing recipe binds their distinct destructor names to `0x0044cbf0` and `0x0092c890`. Independent mapped source bodies further distinguish the behaviors: `modelloader.cpp:2838` dereferences and releases through `FUN_0044dd60`; `staging/blk_00920000_od.cpp:18` dereferences and calls `FUN_004b0ef0`. The relationship supports a private source-type split by member, not an address-only alias. Any split must supply and verify compatible constructors and method bindings as well as both destructors, recompile the complete affected unit, and compare all mapped functions and EH fields before integration. The `PtrA96`/`PtrB96` source views and object offsets should be independently audited for namespace and layout before reuse.

All locations above are observations of original reference fields and the archived BFC production objects. No production source, compiler, oracle, or recipe was changed for this review.
