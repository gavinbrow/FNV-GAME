# Private BGSBodyPart PSA experiment

The private unit 620 PSA member substitution and unchanged unit 621 mirror compiled successfully. The saved `out/phase2-bgsbodypart-psa-proposal/lane-comparison.json` reports 15/15 and 10/10 mapped functions equal in original-versus-mirror code and normalized function relocations, respectively; the reference comparator reports 15/15 and 10/10 matches for both originals and mirrors. This is not a canonical header merge or full class proof.

The full section inventory has 51 sections in each unit 620 object and 59 in each unit 621 object. All corresponding section bytes and relocations match except debug sections, which contain path differences, and one unit 620 constructor cleanup relocation. In that `.text$x` cleanup section, the original refers to `??1FUN_005e3be0@@QAE@XZ` and the mirror refers to `??1TESModelPSA@@QAE@XZ`; their section bytes match. The original surrogate cleanup symbol is absent from the existing unit 620 recipe. The comparison's first normalization maps the native destructor to the separate `FUN_005e3c60_psa` adapter, so it does not establish original-versus-mirror cleanup relocation identity. Do not infer EH completeness from the 15-function result.

The original constructor pushes handler `0x00ef9e3d`, which loads FuncInfo `0x0114b464`. Its relocated unwind-map pointer leads to `0x0114b488`, with seven states. State 6's relocated action is `0x00ef9e32`: it loads the saved object, adds `0x44`, and jumps to `0x0051b950`. The original and candidate COFF constructor `.xdata$x` sections have equal 92-byte contents and equal eight relocation descriptors, including the seven unwind action symbols. Their cleanup thunk sections have equal bytes; state 6 starts at section offset `0x42`, and its relocation at `0x49` changes only the symbol spelling noted above. The offset and member call agree with the original state 6 action.

The reference PSA deleting destructor at `0x005e3c30` also calls `0x0051b950`, BGSBodyPart destruction passes `this + 0x44` to `0x0051b950`, and that routine calls the TESModel destructor at `0x00489070`. The evidence supports a narrow candidate recipe binding `??1TESModelPSA@@QAE@XZ -> 0x0051b950`. The original surrogate cleanup symbol can be mapped to the same target for private original-object EH comparison, but must not be represented as a separate native alias. The compiler-produced EH graph and reference instruction paths support this binding; complete linker placement and full-image verification still remain. No change was made to the shared recipe.
