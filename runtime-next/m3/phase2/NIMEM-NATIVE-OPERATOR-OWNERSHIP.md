# NiMemObject native allocation operator ownership

The current unit-2734 source owns the 62-byte 0x00aa13e0 allocation function with a guessed `void(int)` declaration. The independent pointer-return source candidate compiled with all 43 unit functions and exact reference bytes/relocations; its code preserves the indirect allocator's EAX result. Unit 1664 owns the 34-byte 0x00aa1460 sized-release function, whose source forwards a non-null pointer and size to the manager's scalar-deallocation entry. Both owner units use VC9 SP1 `/MT /O2 /GS /EHsc /Gy`.

The private `nimemobject_native_operators_stage_v2.py` proposal uses the already reviewed public-header allocation declarations and replaces those two free-function definitions with `NiMemObject::operator new(unsigned int)` and `NiMemObject::operator delete(void*, unsigned int)` bodies at the same respective owners. It changes only the two recipe owner symbols and preserves every function address, size, unit flag and all other recipe entries. Source payloads and production-layout minimal closure mirrors for units 1664 and 2734 are under `out/phase2-nimemobject-native-operators-v2/`; they have not been compiled. The separate 750-unit class-key proposal is not changed or combined.

Legacy callers remain an explicit integration issue. The existing recipe has 108 unit-local bindings for the pointer-return `FUN_00aa13e0` symbol and 43 bindings for `FUN_00aa1460`; these bindings are not rewritten or presented as recovered native class names. There are also existing class-operator bindings. Before source installation, prove that every retained legacy call resolves through the actual V7 field/ownership mechanism and that no ordinary linker or COMDAT step requires the removed free-function symbol. Any source-level caller migration needs independently reviewed identity and full affected-function proof.

The API header currently reaches 126 lexical recipe units, with 2,534 functions and 88 listed EH tails; the two new owner includes add units 1664 and 2734 to the scoped proposal. This count is a static include over-approximation, not active preprocessing proof. The operators can alter class new/delete calls and exception cleanup throughout that scope. Verify actual include/first-declaration contexts and class kind, all 46 owner functions plus all affected consumer functions and ordinary EH, independently sourced relocation and literal bindings, scalar/vector deleting fallback semantics and exact production flags. The reference NiRefObject deleting wrapper remains a 46-byte /Od body; the experimental /O2 API fallback is 44 bytes and must not claim that address merely from name. Require actual production objects, weak/COMDAT ownership, exact final image/relocations and runtime before integration.

The virtual allocation protocol's full semantic names, failure behavior and allocator C++ identity remain unproved. This is a bounded native definition hypothesis grounded in the observed ABI and source ownership, not a claim of complete NiMemObject recovery.
