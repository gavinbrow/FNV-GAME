# Scoped TESContainer source evidence

The private `rtti_scoped_registry.py` scans current source and include files with comments and literals masked and braces balanced. The 33 lexical TESContainer definitions comprise 25 syntactically global definitions and eight definitions in named `fnv_*` namespaces. The global reference type name may be compared to the global group; that is an evidence filter, not proof that any definition has the original class layout, access, or virtual interface.

The installed header and the unit 981 sibling are the only reviewed pair derived from the exact former unit 980 class declaration; its sibling overlay remains pending compiler and reference comparisons. No other current global declaration matches that old declaration's token fingerprint. Unit 774 and one-function unit 775 have identical two-method `struct TESContainer` shells, but they omit the canonical class's base and members. `rtti_tescontainer_inventory775.py` creates a private canonical-header experiment for unit 775 only. All emitted code and the mapped function's bytes, relocations and reference comparisons must be checked; matching method spellings do not prove ABI compatibility. Unit 774 has 144 mapped functions and remains a separate, larger experiment.

The scanner reports active textual preprocessor directives without evaluating them, makes no macro expansions, and treats unrecognized braces conservatively as local or unknown. Inactive branches and unmatched conditional braces can distort scope; anonymous namespaces and nested classes are separate categories. `extern` braces are treated as transparent without asserting a specific linkage spelling. A fingerprint compares tokens, not ODR or ABI. The five isolated tests exercise namespace, nested/local scope, masked strings/comments, extern linkage, conditional reporting and anonymous namespaces.
