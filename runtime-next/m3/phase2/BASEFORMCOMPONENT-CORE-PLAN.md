# BaseFormComponent core: staged full-cohort plan

The private generator `baseformcomponent_core_stage.py` produces four reviewable payloads in `../out/phase2-baseformcomponent-core`: three existing wrappers and one new class-definition header. The new core contains only its include guard and the exact existing four-method `class BaseFormComponent` definition. The public wrapper, the `fallout_shared` wrapper and the TESResponse-local wrapper retain their original guard, local support include and ordering, wrapper-local pack directives, and existing size assertion. The generator replaces only each class block with an include of the new core. It does not add an assertion, layout-support dependency, or packing directive to the core itself.

The base recipe is pinned to `d5694cc09e31ff441e38fb546459b11f8c4b0e0f570f252aad1853da563a8160`. The manifest records exact preimage and proposed payload hashes, the complete lexical union of 241 affected recipe units, all 5,817 mapped-function identities and sizes, 367 recorded EH tails, and original/candidate project include closures and unresolved includes per unit. It includes 39 units that lexically reach both public and source wrappers. The private unit 1108 mirror has been materialized as a first diagnostic; it does not reduce the required cohort.

The core deliberately inherits its wrapper's current packing context. The public and TESResponse wrappers retain explicit pack 4; the source wrapper retains its existing ambient context. Therefore this step preserves the present source contexts and does not prove their packing is equivalent, or that every existing BaseFormComponent view has one ODR-safe definition. The 20 other exact-body but pack-unproven views, all different constructor/destructor/renamed views, and namespace adapters remain outside the payload. Shared include guards may suppress apparent lexical overlaps; actual compiler preprocessing decides which definitions are active.

After the active build and controls release the exclusive lane, verify as follows:

1. Recheck the pinned recipe, source preimages, compiler, reference and default selection hashes. Archive each actual production cohort object before private compilation. No object hash from an earlier build is assumed current.
2. For every manifest unit, run `baseformcomponent_core_mirror.py --unit N`, then `rtti_mirror_compile_d569.py --out <that mirror>` in the serialized compiler lane. The compiler validates the reviewed recipe transitions, mirror contents and production include order, and captures `/showIncludes`. Any unexpected project/system include, compile failure or unresolved guarded collision blocks the batch.
3. Run `baseformcomponent_core_compare.py --unit N --production-object-sha256 <archived hash>` for every unit. It requires every mapped function to match between production, original and candidate, and compares reference fields. It derives compiler literal-label changes only from matching source-bound pool content and offsets. If the strict production baseline is incomplete, separately explain the normal assembler's source sidecar/global bindings; do not weaken the oracle or count an unknown baseline as a pass.
4. Independently compare every one of the 367 recipe EH tails, including code bytes, relocations and ownership, with the unchanged ordinary function/EH oracle. Named EH section-tail equality in the helper is supplementary, not a substitute for those tail checks. Inspect emitted class/RTTI/vtable sections, weak symbols, thunks, ownership, dynamic initialization and unmatched additional object sections; no silent pruning or assumed class placement.
5. Re-derive any changed production-location literal labels from the actual installed objects and recheck the entire affected cohort. Only a reviewed, guarded multi-file transaction with rollback/recovery may modify the four files. Run the full canonical image, exact relocation-directory, source coverage, all required negative controls, repeated build and semantic gameplay/clean-exit gates. No coverage gain or native class completion is claimed from matching the declaration alone.

The closure is a syntactic over-approximation: conditional branches, macro-generated includes, and system includes are not resolved statically. `/showIncludes` and compiler/preprocessor evidence are mandatory. A failed unit or unresolved mapping is an explicit blocker, not permission to narrow the 241-unit cohort.
