The implicit-destructor private candidate has 15/15 strict unit 620 function matches under the two explicitly listed experimental bindings, and its unchanged unit 621 control has 10/10. The native constructor and implicit destructor are compiler-generated. The 19-byte destructor matches original `0x0051b950` outside its relocation, whose original target is `TESModel::~TESModel` at `0x00489070`. The 44-byte deleting wrapper matches original `0x005e3c30` outside its two relocations, whose targets are that destructor and `operator delete`. The emitted vector-deleting symbol is a COFF weak external with search characteristics 2 and a scalar-deleting fallback; actual final-link resolution still requires validation. Original constructor unwind state 6 independently reaches `0x0051b950` with `this+0x44`.

The candidate and reference root locator and full three-base RTTI structure match in the existing structural comparator. `nested-graph-evidence.json` additionally follows every root base descriptor to its own nested hierarchy and type descriptor, validates the relocated reference pointers, and compares names, subtree counts, parent relationships, PMDs and attributes. All three nested graphs match. The reference type descriptors point to `0x010f1ee0`, the unique source-unit mapping of the type-info vtable. This verifies graph structure and identities, not final placement of candidate records.

`graph-experimental.json` compares seven emitted virtual slots to the first seven observed reference pointers. They match under the explicit entries in `graph-experimental-unit.json`, including the weak deleting-destructor fallback. The first four targets have supporting TESModel source bodies; getter/setter signatures and the experimental native method names remain source hypotheses. These are proposed bindings, not independently existing native symbol mappings. The following reference word is also a relocated code pointer, then a zero and a mapped string literal. Its ownership and the full table extent remain unresolved; the helper correctly reports the emitted seven slots do not cover its eight-pointer observed prefix.

The two unit 620 constructor/destructor `.xdata$x` records match original bytes and relocation descriptors. Cleanup thunk section bytes match; the changed relocations name the native implicit PSA and virtual TESModel destructors, with reference state-6 and base-destructor targets established independently. Unit 621 EH section multisets match. Candidate `.rdata$r` metadata introduces additional records, and no full image, link placement or runtime gate has been run for this candidate.

This is a reviewable narrow source-and-recipe proposal, not an integration-ready complete class: canonical header reuse and source signatures, all metadata placements and relocations, the eighth pointer, full table ownership, linker weak-alias resolution and full-build controls remain open.
