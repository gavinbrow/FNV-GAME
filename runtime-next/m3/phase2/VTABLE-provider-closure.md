# V7/M3 deleting-destructor provider closure (private research)

`vtable_provider_closure.py` audits the exact `??_E` primary names for BGSEncounterZone and TESModelPSA. The private JSON snapshot hashes the successful recipe objects, configured EH variant, current generated M3 object groups, both V7 CRT archives, and controlling manifests; inputs are rehashed after the scan. No matching strong primary appears among the present objects or archives.

The snapshot is **incomplete**: the V7 contribution manifest references 1,087 distinct target IDs, but their underlying `build-v7/obj/<id>.obj` files are not present. The accepted contribution pieces and EH pieces are serialized data snapshots, not a complete COFF symbol table. Their recorded relocation sites contain no exact primary-name use, but that is not proof that their original object files had no primary definition.

V7 schedules successful recipe objects plus the configured unit-2757 EH-variant object; the variant is used only for exception pieces and does not replace the parent function. It reads serialized verified contribution and contribution-EH pieces, and independently searches compiler libraries in libcmt then libcpmt order for CRT code. M3 reads generated object groups 0 through 3 from the current manifest as data-definition pieces; this is not a conventional global linker input pool. Exact configuration toggles and manifest provenance must be established for the final archived run.

The resolver itself is not MSVC library extraction: direct recipe function/name and symbol maps, local ranges, imports, and verified EH mappings resolve first. V7 can then apply EHBIND, ICF, sized-delete and name/field overlay paths under their configuration gates. Current ICF and named overlay maps have no exact entries for the two primary names; field-specific overlays are keyed by the actual relocation address and require a candidate-specific check. `SEARCH_LIBRARY` characteristic 2 remains unsupported, and the fallback cannot be enabled solely from this scan. Real provider selection, omitted contribution COFFs, other potential archives/default libraries, field-specific overrides, generated destructor placement, and class ABI remain open.
