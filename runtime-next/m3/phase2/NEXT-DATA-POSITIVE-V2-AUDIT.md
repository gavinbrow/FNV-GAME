# Next-data positive v2 artifact audit

The archived positive v2 data inputs and output image pass the read-only artifact audit in `out/phase2-next-data-positive-v2/evidence/data-artifact-audit.json`. Its manifest contains 8,268 kept M3 entries with the same range union as the previous accepted selection, and its M3/DV1 ranges are disjoint. Actual archived `.data`/`.rdata` coverage is 1,613,010 bytes; five `.tls` bytes are separate. M3 contains 340,207 zero and 722,766 nonzero reference bytes, DV1 185,116 zero and 364,921 nonzero.

The actual generated COFF contains the expected source-view NiPoint3, two SIMD and Cost245 symbols and extents, with original relocation sites retained in their tails and Cost245 head. The two SIMD definitions and their pseudo-unit records carry 16-byte alignment. Reconstructing the default reversed `.rdata` chunk order from the archived data-v3 manifest and actual output PE places `0x010cb620` and `0x010cb630` at final VAs `0x005316c0` and `0x005316d0`; both are aligned and their actual PE bytes match their source bytes. The archived layout capture identifies default layout G. Relocation-target correctness and final-image ownership remain subject to the build and independent replay evidence.

The independent staged library hook replay in `evidence/data-library-replay.json` uses the archived placement, the archived M3 claims and non-library DV1 claims, archived symbolic fields and chunk layout, and hash-matched helper source. It validates all 405 selected pieces / 16,730 bytes against compiler archives, members, source sections or exact split-piece identities, and matches the archived DV1 library pieces.

**This is not an accepted full gate.** The v2 freeze did not include the consumed `cost245_records.py` helper; a corrected fresh v3 positive and its full controls/repeat are required. This note does not update the accepted coverage partition. Cost245 relocation-bearing integer fields remain source-view integer transports; native pointer semantics remain unproved.
