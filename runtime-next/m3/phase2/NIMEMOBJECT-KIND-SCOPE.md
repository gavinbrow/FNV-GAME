# NiMemObject public class-key correction scope

The reference NiRefObject hierarchy names its empty base `.?AUNiMemObject@@`; the existing public class declaration emits `.?AVNiMemObject@@`. Both the definition in `include/NiMemObject.h` and its earlier forward declaration in `include/layout_support.h` use `class`. A private two-unit experiment changed both to `struct`: units 1484 and 1503 compiled with valid include traces, all 13 mapped functions and relocations remained strictly equal, and the emitted NiRefObject graph acquired the correct base name and PMD +4. Its scalar-deleting slot still has unresolved ownership and a 42-byte emitted fallback versus a 46-byte reference wrapper. No class-completeness or global ODR claim follows.

The historical `generate_headers.py` named in the supplied header comments is absent from the accessible project/tool inventory, including the specifically checked path. The private deterministic `nimemobject_coherent_kind_stage.py` therefore creates a reviewable correction hypothesis using exact input hashes and scoped replacements. It changes the public empty definition's keyword and 26 syntactically top-level support-header forward declarations, preserving the explicit `public:` and all other text. It does not change flags, recipe entries, function addresses or sizes, and does not rewrite independently defined classes or namespaced adapters.

The 26 support forwards include 17 headers sharing `FNV_LAYOUT_SUPPORT_H` and nine using other guard spellings. Which declaration appears first depends on actual include order, guards, preprocessor branches and potentially other declarations. The complete static recipe-closure over-approximation for those 27 files is `out/phase2-nimemobject-coherent-kind-consumers.json`: 750 of 2,995 recipe units, 26,446 mapped functions and 866 listed EH tails; 126 affected units lexically include the public definition. This is the complete cohort under the current syntactic quoted-include scanner, not a claim that every path is active or that macro-expanded/system includes and first declarations are resolved.

Ninety-four affected unit closures also contain other NiMemObject lexical views outside the payload. Their 71 source files contain 81 conservatively scoped definition leads: 60 syntactically global and 21 namespaced, as recorded in `out/phase2-nimemobject-coherent-kind-identity-blockers.json`. Scoping does not prove their native identity, field layout or active branch. They remain untouched and cannot be joined merely because their spellings match. The first-declaration status of the remaining untested contexts is explicitly unresolved.
