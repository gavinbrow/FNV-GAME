# Phase 2 RTTI name investigation

The 207,636-byte produced-but-unspliced total is a disjoint Phase 1 coverage category, not a verified RTTI-only quantity. Historical data-v1 diagnostics include unplaced synthetic-name type descriptors, unresolved RTTI dependencies and incompatible vtable slots; some figures overlap or count duplicate pieces. A successful class-name experiment does not automatically recover those bytes, repair a hierarchy, or establish a vtable layout.

`rtti_inventory.py` records a read-only, reference-assisted join from unit vtable-symbol address through the original relocated COL pointer and its relocated type-descriptor pointer. The saved inventory has 3,880 accepted unit symbol references grouped into 2,187 distinct vtable/COL/type-descriptor tuples; 259 references fail those narrow chain checks. Ninety tuples have both a simple matching named vtable spelling and a simple synthetic spelling at that same address. These are address/name leads only. Multiple declarations, different bases, independent surrogate classes and folded aliases can share a reference VA; none proves source identity, complete object extent, compiler ABI, or recoverable bytes. The generated inventory contains addresses, names and relative source paths, not object bytes.

## First bounded experiment: hkpConstraintViewer

The original reference type name is `.?AVhkpConstraintViewer@@`, with type descriptor at `0x011b616c`. Four unit-2501 vtable names involving `FUN_00d698b0` lead through separate reference COLs to that descriptor. The source at `src/havok/physics/utilities/visualdebugger/viewer/dynamics/hkpconstraintviewer.cpp` declares `class FUN_00d698b0` with multiple bases and implements its constructor at `0x00d698b0`; the original type spelling is absent as a whole identifier in the scanned source/include roots, the synthetic identifier appears in only this TU, the class/struct discriminator agrees, and this TU has only the system `<windows.h>` include. This supports an isolated name experiment, not an assertion that its current `D698B0Base`/listener hierarchy is original. The same addresses also have separate `FUN_00d69920_cls` surrogate symbols, reinforcing the need for collision and ownership review.

The baseline's 40-byte `M3_011b616c` W scaffold already covers this descriptor area. The 8-byte header plus NUL-terminated original type name is 34 bytes; the 40-byte W range has original relocations at offsets 0 and 36. A 34-byte descriptor must not replace the entire 40-byte W object, and no increase in object-byte coverage can be claimed merely by producing it. Preserve the remaining bytes/relocation and prove nonoverlap before any future selection change.

`rtti_hkp_viewer_overlay.py` verifies the exact source and unit-recipe hashes, one source occurrence, absence of the proposed original identifier in approved source/include files, class spelling, source token count and include form. It writes a whole-TU token-renamed copy and manifest only to the new, exclusive private `m3/out/phase2-hkp-constraint-viewer` directory. It never edits protected source or frozen selection; four synthetic tests exercise the transform and rejection paths. `rtti_hkp_viewer_compile.py` is the separate, single-unit SP1 driver, compiling original and overlay sequentially with unit 2501's exact `/MT /O2 /GS /EHsc /Gy` flags into that private directory, with exclusive outputs. It requires a coordinated exclusive compiler lane; it does not install or integrate the result.

For verification, `rtti_hkp_viewer_compare.py` hash-checks original and overlay objects, builds a remapped unit manifest in memory, and reports all 16 mapped function bodies and normalized relocation targets, plus existing reference comparator results and the descriptor section. Compiler acceptance alone is not success: require exact function bytes and reference-resolved relocations, explain any changed names, compare emitted descriptor including its relocation target/addend, and independently inspect COL hierarchy, base descriptors, vtable slots and generated symbol ownership. A nonmatching base or slot blocks the dependent metadata even if the name string matches. A separate test must demonstrate safe split/replacement of the W owner without overlap or lost relocation before any opt-in splice or image build.

Two attractive leads were deliberately rejected: `AudioLoadTask` already appears as differently scoped source declarations, while `BGSTerrainChunkLoadTask` already coexists with the synthetic `FUN_006fbb10` in one source and has different declared bases. Co-addressed symbols do not justify renaming either. `BGSEncounterZone` likewise already has named and synthetic forms; its original-name descriptor is already produced by DV1, so it is not a new-byte opportunity.

## Concrete next action

The isolated name experiment is complete. Before any native-class integration, investigate the independently observed hierarchy mismatch: the reference has seven base descriptors, the overlay has six, and listener attributes differ. Build an evidence-only graph specification and verify the original relationships and virtual slots against source and the MSVC ABI; see `HKP-HIERARCHY.md`. Separately, a future descriptor-ownership experiment would need a reviewed, nonoverlapping 34-byte descriptor plus six-byte W remainder and proof that the relocation at W offset 36 is preserved. Keep the current W owner, protected sources and default selection unchanged until those issues are resolved. No byte-coverage increase or complete native-class recovery is claimed.


### Isolated unit compile and preliminary comparison

The verification worker compiled original and overlay unit 2501 sequentially in the private directory using VC2008 SP1. Both returned 0. The overlay object emitted `??_R0?AVhkpConstraintViewer@@@8` in a 34-byte `.data` section with a single relocation at offset 0; its remaining bytes match the corresponding reference prefix. The existing reference comparator reports all 16 mapped functions matching for both original and overlay. These results do not prove full class hierarchy, vtable semantics, safe W replacement or game behavior.

The first original-vs-overlay relocation comparison reported one false mismatch because its initial text replacement also altered an unrelated string-literal symbol; that report remains preserved. The corrected, independently checked `coff-comparison-v2.json` normalizes only exact unit-mapped decorated symbols: all 16 function byte sequences and normalized relocation sets agree, and the descriptor type-info relocation resolves to the reference target. The original and overlay also match the reference comparator for all 16 mapped functions. This completes the isolated name experiment only. As documented in `HKP-HIERARCHY.md`, the original hierarchy has seven base descriptors versus six emitted by the overlay, with differing listener attributes; dependent native hierarchy and vtables remain blocked, and no coverage gain is claimed.
