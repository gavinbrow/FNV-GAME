# BGSBodyPartData native destructor and provider-index plan

Private unit621 mirror: `phase2-bgsbodypartdata-native-dtor-v1` is based on the accepted 825d recipe and adds a virtual destructor whose body calls the existing qualified `ClearData`. The source owner in unit2656 uses the same semantic operation but its surrogate destructor is 127 bytes; the current native implicit destructor is 86 bytes. Exact compiler-generated vptr stores and destructor calls must arise naturally and match in the private fixture. Unit621 has ten pre-existing mapped functions; unit2656 has 174. No ownership is transferred yet.

If and only if all 10 unit621 functions, the new 127-byte native body, its normal relocations and complete ordinary EH agree with independently source-owned original spans, a later separately guarded recipe proposal may remove the unit2656 surrogate destructor mapping and add the native unit621 symbol at the same original span. The unit2656 44-byte wrapper and all 174 donor functions must retain their original bodies and reference checks; its old destructor call name needs a source-supported owner mapping, not a reference-fed alias. Audit all affected callers, include closures, ODR and compiler-generated deleting wrappers. No vtable can be selected while E fallback remains unresolved.

`psa_weak_provider_index.py` accepts only a complete archived successful compile log, matching recipe, clean frozen-run evidence and a full object directory. It hashes all objects at scan start and end and records exact E/G/destructor primary and weak-aux metadata. Its index deliberately excludes CRT, V7, M3 and data-v1 providers. A complete class-specific search proof additionally needs actual two CRT archives and all code/data members/linker indices, exact V7/ICF/overlay/import inputs, actual selected M3 and DV1 pseudo-units, and fresh placed state. Source-backed G and destructor bodies and physical table/field ownership must pass independently. No generic weak mode or E address mapping follows from the index.
