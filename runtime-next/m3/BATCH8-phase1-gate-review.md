# Phase 1 completion gate review

This is a documentation review, not a build result or a change in scope. `PLAN-M3.md` defines Phase 1 as turning 15,050 `extern DAT_` declarations into real definitions, while the initial design and subsequent notes defer or progressively expand particular categories. `TODO.md` still lists unresolved typed declarations, file-backed zero globals, `.bss` definitions, and real types for the 849 KB of address-named W scaffolding. The handoff also lists these as future work. The three files describe slightly different phases and sequence, but none records user acceptance that those items no longer form part of the original Phase 1 outcome.

Consequently, successful Batch 8 builds, controls, gameplay, repeatability, and default promotion would establish a verified **current splice milestone**, not completion of the original all-declarations Phase 1. Default promotion and evidence records alone do not produce the missing definitions or establish source identities. A narrower “Phase 1 implementation milestone” could be called complete only if its scope is explicitly stated and the user accepts that scope; otherwise keep Phase 1 open. Promoting the default is a separate operational decision and must be supported by fresh checks of the actual promoted default. Phase 2 generated source changes require the user's stated prior approval; completing a Batch 8 milestone or promoting a default is not that approval.

Suggested checklist wording, with boxes checked only after recorded results actually pass:

- [ ] **Batch 8 verification:** record the frozen selection filename and digest; build the unchanged default baseline; build the selected positive; confirm expected reference SHA-256 and exact relocation-directory bytes; run value and pointer negative controls and record both the intended mutation and expected failure/different hash; repeat the positive; pass the extended menu, load, play, cell-change, quicksave/load, and exit harness. Record paths, switches, counters, and failures or reruns.
- [ ] **Default promotion:** after the above passes and the chosen clean-running criterion is met, promote the verified selection and switches; then test and record the promoted default itself. Until then label it opt-in. Do not assume a prior opt-in positive establishes the behavior of changed defaults.
- [ ] **Phase 1 source-definition completion:** resolve the remaining source declarations, aliases and extents; account for uncovered bytes and non-spliced produced units; define and verify the applicable file-backed zero ranges; resolve `.bss` definitions/layout separately from file-byte coverage; replace or explicitly account for W scaffolding with supported source types. Preserve unresolved cases in inventories until evidence supports them. Imported/IAT or other builder-rewritten ranges must be accounted for according to their actual origin, not attributed to M3 objects.
- [ ] **Phase 2:** request and receive user approval before Phase 2 generated source changes; separately record the approved scope. RTTI, classes, and vtables remain Phase 2 work.

For the Batch 8 result, report only measured new and cumulative counts from the final verified run. Identify the sphere selection as a 2,688-byte accessed prefix whose complete original array extent is unresolved; identify synthetic scalar/pointer names as storage-proven objects rather than resolved original symbol identities. Whole-array command declarations, disputed types, and unknown tails stay deferred. W objects are compiler-produced address-named typed scaffolding, not 849 KB of established original source types. `.bss` has no file bytes, so cannot be counted toward initialized-byte coverage. Per-inventory counts 7,171 unit-symbol addresses and 7,710 source-inventory BSS addresses are distinct measures, not additive counts of objects. The rewritten import/IAT/TLS ranges, unit pieces that compile but do not splice, and code/data provenance categories should retain their separate accounting.

The Batch 7 selector's `multi-type` and `global-non-scalar` numbers describe intervals, not object extents or trustworthy current type classifications: the selector removes a second character from the encoded type in `decl_class`. The prior OFF attribution is unsupported. Preserve old values as historical snapshots and use the Batch 8 reports for current evidence; do not silently relabel those buckets as precise symbol families or add whole interval counts as progress.
