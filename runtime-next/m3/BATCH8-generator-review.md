# Batch 8 generator review

Read-only review of `b8_select.py`, `gen_m3.py`, the frozen selection, and build-driver environment propagation. The selector was executed with only its destination replaced by a temporary file; its output matched the frozen JSON byte-for-byte, SHA-256 `f0539b28be3c58729bb994534e19bc1d1410f80b88e027bdea9363878129990b`. It adds 61 definitions, 2,843 bytes (248 zero, 2,595 nonzero), to the frozen Batch 7 entries. The selector checks raw bounds, chunk containment, saved coverage and recorded rewritten ranges, internal overlap, fields and pointer targets. These checks depend on the saved inputs and recorded rewritten ranges.

An isolated VC2008 SP1 object compiled actual `build_entries` and `cpp` output for all 61 added entries; actual `check()` found no errors, dynamic initialization, byte mismatches, section errors or relocation mismatches. The set included eight pointer definitions and ten explicit file-backed zero definitions. Symbol discovery resolved every fresh `M3_` name. These synthetic storage names make no native source-linkage or alias claim. This was a temporary object check, not a complete image build or gameplay test. Earlier targeted fixtures checked zero arrays and W objects in both `.data` and `.rdata`, and verified the b8p target mutation. The revised b8v avoids the observed wrap-to-zero file-backing failure.

The generator has an existing prune loop: a failed individual object check can remove a selected definition and still return success after convergence. A matching final image hash alone does not prove all selected bytes came from the intended objects. Gate integrated evidence on selected and kept counts matching, zero dropped entries, correct selection digest, and absence of provenance errors. Also, a missing configured selection currently invokes `select()` and falls back to a generated pilot selection; fail closed on missing requested input when promoting the default. The b8p branch falls back to an earlier pointer if no Batch 8 pointer is present; inspect the recorded mutation to establish which pointer was exercised.

For a later default promotion, resolve effective M3, DV1, EXT, and selection settings once in `build_all.py`; propagate those exact settings to the child environment before every step and derive the summary and selection hash from the same values. Default them to the verified Batch 8 settings while preserving a documented explicit opt-out and overrides. When opting out, remove or normalize inherited `DV_M3`, `DV3_SKIP`, and DV1 switches so downstream verify, snapshot, and image steps cannot observe contradictory mode flags. The direct subcommands currently interpret their own environment and remain opt-in unless their standalone behavior is deliberately changed. With DV1 enabled, `--skip-data-v1` also skips `dv1_splice.py`; prohibit it or validate all reused artifacts, since otherwise a previous DV1 output could be consumed. Repeat clean builds, controls, relocation checks, and the extended harness before promoting the default.

## Final selection review

The later `batch8_final_selection.json` is distinct from the original 61-entry pilot selection. A temporary-destination run of `b8_select.py --final` reproduced its exact bytes and SHA-256 `42d84f21776429e139502ebe391302d7c8b36f1833a6403d96009a99bbabcfe7`: 64 additions totaling 36,597 bytes. The two original one-byte string heads are each replaced by one partial array at the same address; no duplicate heads remain.

`tools/test_b8_final_independent.py` invokes actual `gen_m3.main` with a temporary 64-entry input, temporary manifest and log paths, and an isolated VC2008 compiler adapter. The positive run retained and checked all 64 without drops. Actual `b8v` and `b8p` branches each retained all 64; the temporary object showed the intended value change and changed pointer relocation respectively. The R record definitions, external declarations, and other additions compiled together. This exercises the final additions in isolation, not the full Batch 7-plus-final image, gameplay or default promotion.
