# Batch 8 other-name interval tail review

The largest skipped interval is `[0x01000001, 0x010113c0)`: 70,591 bytes, including 18,212 nonzero. The start is not reliable evidence of a real char object: `hkptoicountviewer.cpp:971` retains an `extern "C" char` declaration, but the current use at line 1056 passes the numeric literal `0x1000001` as a flag. The historical C-decorated unit key is consistent with the old spelling but does not prove object ownership. Within this interval, no saved data-v3 labels, DAT inventory addresses, or unit symbol target values were found. Those searches do not rule out undiscovered names or references.

The bytes contain 6,214 aligned original DIR32 sites, all targeting `.text`; the first begins at `0x01000094`. Of these, 5,754 targets match functions recorded in `units.json`: among them 2,772 status callbacks, 884 optimized global object initializers, 636 float scale callbacks, 547 global object initializers, and 300 float call initializers. No printable NUL-terminated strings of eight or more characters were found. This strongly suggests CRT initialization-related pointer tables, but does not prove exact table boundaries, ownership, or every target's role. This source-dependent CRT initialization work belongs to Phase 3 under the project plan; no generic interval-tail objects or inferred complete extents are proposed.

Other large intervals do have independently supported Phase 1 prefixes. `inventory/b8_string_prefixes.json` records three NUL-terminated format strings at `0x0104ae98`, `0x0103ae48`, and `0x0103aef0`, with respective prefix lengths 148, 165, and 163 bytes. Their declarations, printf-style calls and original bytes support those accessed prefixes, not complete object extents. The latter two overlap one-byte Batch 8 heads and require replacement, not overlay. The candidates pass saved chunk, field, relocation, existing placement, recorded rewrite, data-label and interior unit-symbol checks, and a temporary VC2008 object generated by the actual M3 routines matched bytes, sections and relocation expectations. Further full integration and negative controls remain required. These use synthetic M3 names and do not resolve native aliases.

The filename-shaped bytes at `0x0106e4e0` terminate after 91 characters (92 bytes including NUL). Although source passes its address to `FUN_00404eb0`, that function forwards it to `FUN_00404f00`, whose current implementation does not read the filename argument. The sequence is deferred pending evidence of a string read. The two untyped larger heads `0x0105bb14` and `0x01077eac` also have printable leading bytes, but their current call signatures do not establish string access or extents. An interval ending at a later address is never itself evidence of the original object's extent.
